Cała konfiguracja

{
  "permissions": {
    "deny": ["Read(./.env)", "Bash(git push --force *)"],
    "ask":  ["Bash(git push *)", "Bash(gh pr create *)"]
  },
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{ "type": "command",
        "command": ".claude/hooks/guard-bash.sh",
        "onFailure": "block" }]
    }]
  }
}

nigdy, bez pytania

Hook: odmowa z powodem

# .claude/hooks/guard-bash.sh (fragment, uproszczony)
deny() {
  jq -n --arg r "$1" '{hookSpecificOutput: {hookEventName: "PreToolUse",
    permissionDecision: "deny", permissionDecisionReason: $r}}'
  exit 0
}

if grep -Eq '(^|[[:space:];&|])git[[:space:]]+commit' <<<"$cmd"; then
  python3 -m unittest -q || deny "Commit zablokowany: testy nie przechodzą."
fi

Co mówi dokumentacja

Hooki działają przy każdym wywołaniu

“Each tool call in the code goes through your deny and ask permission rules and PreToolUse hooks under the tool’s usual name.”

Klasyfikator widzi kod, nie wartości

“the classifier reviews each piece of code before it runs, not each tool call. It doesn’t see values computed at run time … so keep rules or hooks for calls you must control.”

JavaScript działa poza sandboxem

“The JavaScript itself and its file, web, and MCP tool calls run outside the sandbox.”

code.claude.com/docs/en/code-mode

Im więcej autonomii, tym ważniejsze hooki.
